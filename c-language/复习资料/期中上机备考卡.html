上机题的五步通关流程

上机不是"想起来就敲"，是按固定顺序走。每一步都别跳。

STEP 1读题：圈出输入格式、输出格式、括号里的特殊说明
STEP 2写状态表：有哪些变量、初值多少、谁改它
STEP 3先写骨架：include、main、return 0，先编译一次
STEP 4一次补一块，每补一块编译一次
STEP 5边界自测：0、1、最大值；输出与样例逐字符比
为什么先写骨架？ 编译错误分"语法错"和"逻辑错"，先让语法过关，后面的报错就只剩逻辑，定位快一半。
最常见的翻车： 一次写 60 行再编译，然后面对一整屏报错不知道从哪改。
2

数据与运算：四个必背数字

这一块几乎每道题都会用到，只有四个知识点。

① 整数除法会截断。 除号两边都是整数，结果就取整。
5/2 → 2　5.0/2 → 2.5　5/2.0 → 2.5
要小数就写 5.0/9.0。
② 强转是截断，不是四舍五入。 (int)3.9 → 3　(int)(-3.9) → -3
想要四舍五入：(int)(x + 0.5)
③ i++ 和 ++i 区别只在"先用还是先加"。 
i = 5;
printf("%d", i++);   // 输出 5，之后 i=6
printf("%d", ++i);   // i 先变 7，输出 7
考试里除非专门考，别在一条语句里对同一变量多次自增。
④ 字符就是 ASCII 码。 'A'=65　'a'=97　'0'=48　大小写差 32
c = c - 32; 小写转大写　　c = c + 32; 大写转小写
表达式里的数学写法不能用： 3 < x <= 10 在 C 里恒为真，必须写 x > 3 && x <= 10。
3

输入输出：格式对不上，全白写

上机判题是逐字符比对，多一个空格都是错。

格式用于例子
%dintprintf("%d\n", x)
%ffloat / 输出 doubleprintf("%.2f\n", y)
%lfscanf 读 doublescanf("%lf", &y)
%c单个字符printf("%c", c)
%s字符串（char 数组）scanf("%s", s) 不加 &
scanf 三件事，写完数一遍：
① & 的个数 = 变量个数（%s 除外）
② 类型配对：double 用 %lf，用 %d 会读到垃圾值
③ 格式串里有什么，输入就敲什么："%d,%d" 输入要带逗号；末尾不要写 \n
%.2f = 保留两位小数：不足补零、超出四舍五入。
1234.567 → 1234.57　1.5 → 1.50
上机检查输出：把程序的输出和题目样例并排贴在一起逐字符看，别用眼睛扫。空格、换行、大小写、单位，全算内容。

分支：三个坑 + 一个模板

坑 1：if (...) 后面加了分号。 if (x > 0); 表示"条件成立就执行空语句"，后面的代码永远执行。
坑 2：= 和 ==。 比较必须写两个等号。if (x = 5) 是赋值，条件恒为真。
坑 3：switch 不能判断范围。 case (x >= 3) 是错的。switch 只能"一个值对应一段代码"，见比较符号就换 if。
另外 漏 break 会往下穿，执行完本 case 继续跑下一个。

分段类题目（电价、个税、奖金、打车）全都是同一个模板：

// 每一档 = 上一档累计 + (本档上限 − 上档上限) × 本档税率
// 奖金例：10万以内 10%，10~20万的"部分" 7.5%
if (I <= 100000)      bonus = I * 0.1;
else if (I <= 200000) bonus = 10000 + (I - 100000) * 0.075;
else if (I <= 400000) bonus = 17500 + (I - 200000) * 0.05;
最容易错的地方：把"档宽 × 税率"算成"整段金额 × 税率"。
20 万那一档的增量是 (200000−100000)×7.5% = 7500，不是 200000×7.5% = 15000。
5

循环：三要素 + 边界三问

三要素（缺一个就死循环或少跑一次）： 初值（从哪开始）· 条件（做到什么时候停）· 增量（每轮怎么变）。 
sum = 0;                          // ① 初值：累加器先清零
for (i = 1; i <= n; i++)          // ② 条件　③ 增量
    sum = sum + i;
写完循环，回答三个问题：
① 一共执行几次？
② 最后一次循环时，i 是多少？
③ 循环结束时，i 是多少？
例：for (i = 0; i < n; i++) → 跑 n 次，最后一次 i = n−1，结束后 i = n。
死循环的头号原因： 循环体里忘了让变量变化（i++）。
上机时如果程序"卡住不动"，先查这个。
二重循环：内层管一行，外层管换行。 
for (i = 0; i < n; i++) {        // 行
    for (j = 0; j < m; j++)      // 列
        printf("%d ", a[i][j]);
    printf("\n");                // 换行：内层外面、外层里面
}
找"任意两数"时，内层从 j = i + 1 开始，避免自己和自己比、避免重复。
语句作用
break立刻跳出本层循环
continue跳过本轮剩下的语句，直接进入下一轮

一维数组：五个模板

定义与初始化： int a[1005] = {0};　长度写常量、不写 a[n]；一定加 {0}，否则是垃圾值。

① 求和

s = 0; for (i=0;i<n;i++) s += a[i];

② 最值

mx = a[0]; 从 a[0] 开始，不能取 0（全负数就错）

③ 桶计数

cnt[x]++; 下标就是被统计的值本身

④ 双指针

i=0; j=n-1; 相向走，用于回文/反转

⑤ 冒泡排序

相邻两两比较，顺序不对就交换，外层 n−1 轮

何时用数组

要回头再看一遍数据吗？要就用，不要就边读边算

// 冒泡排序模板
for (i = 0; i < n - 1; i++)
    for (j = 0; j < n - 1 - i; j++)
        if (a[j] > a[j+1]) { t = a[j]; a[j] = a[j+1]; a[j+1] = t; }
数组三个必错： ① 忘 = {0} → 垃圾值； ② i <= n → 越界（越界不报错，只是结果错）； ③ scanf("%d", a[i]) 漏 &。

4–5 星难题：怎么拆、怎么拿部分分

难题不是"更难的语法"，而是"规则更多、步骤更长"。它考的拆解能力，不是记忆。

难题的四种长相（对号入座）：

类型特征打法
多规则组合一堆"如果…则…"（车牌限行、工资、计价）每条规则写成独立 if，别合并
过程模拟描述一个过程（跳一跳、报数、日期推进）while + 状态变量，把"当前值"存住
数字规律质数、完全数、亲和数、递推先手算 5 项列表，找差/比/周期
字符串/数组处理统计、回文、排序、中位数套模板：桶计数、双指针、冒泡

拆解四步（卡住时按这个顺序做）：

① 抄规则把题目里每一条要求抄成一行中文，编号
② 举小例自己造一个 3–5 个数据的小例子，手算出答案
③ 定状态列出：当前值、计数、标志位，各从几开始
④ 先暴力写最直白的版本，能过样例就交，再优化
暴力版也是分。比如"求第 k 小"先用排序写，"判素数"先试到 n/2 不优化——只要能过一部分测试点，就比空着强。OJ 按测试点给分，不是全对才得分。
难题最常死的地方（不是算法，是这三处）：
① 规则的边界含不含（"低于或等于" vs "小于"）—— 抄规则时就标出来；
② 状态变量忘了初始化 / 忘了在每轮重置；
③ 输出格式（多一个空格、少一个换行）。
